# ADR-0018: Iceberg physical removal and reader drain
- Status: accepted (G8); each step verified on Iceberg 1.12.0 / Spark 4.1.3 in the G8 spike (MoR and CoW), timings to be measured in g8-check
## Decision: a maintenance window, not live mode
Logical deletion runs under load. Physical removal runs in a **window**: wait until the logical phase is done, stop `spark-streams`, drain the embedder, run the steps below on bronze, silver and every `quarantine_*`, restart. Requests are batched; physical lag = window verified-at minus request time. Live mode (writers and readers running) is deferred: its cut would be the committed_at of the rewrite snapshot, expiring only snapshots older than it, with every reader's pointer at or after it. It is not implemented or claimed.
## Steps, in this order
1. `rewrite_data_files(where = footprint, delete-file-threshold=1, min-input-files=1, partial-progress.enabled=true, remove-dangling-deletes=true)`. Pass every option: in 1.12.0 a lone file with a position delete is rewritten even by default, but the old delete file stays referenced until `remove-dangling-deletes` runs. `maintenance.COMPACTION_OPTIONS` uses `min-input-files=2` (ADR-0015), so G8 overrides it.
2. Drop every non-`main` tag and branch.
3. Drain the embedder: its pointer equals the current bronze snapshot and `pending` holds no footprint entity; then stop it. Its incremental scan skips delete/overwrite/replace snapshots (ADR-0016), and if its pointer snapshot is expired it falls back to a full bronze rescan, which must not happen while the footprint is being removed.
4. `rewrite_manifests`, then `expire_snapshots(older_than = now, retain_last = 1)`. The spike showed that rewrite -> expire -> orphans is **not enough**: a surviving manifest still held a `DELETED` entry whose `lower_bounds`/`upper_bounds` contained the canary (bounds keep short strings whole, truncated at 16 characters). Rewriting manifests and expiring again removed it on both MoR and CoW. `older_than` must be a literal, so Python computes it.
5. `remove_orphan_files(older_than = now, prefix_listing)` through the **Action API** (`SparkActions.deleteOrphanFiles(table).olderThan(ms).usePrefixListing(true)` via py4j). The SQL procedure refuses an interval under 24 hours (the alternative, `spark.testing=true`, must be set before the session exists). This drops ADR-0015's "older_than >= longest write" safety, which is sound only because the window has stopped every writer; orphans from a SIGKILLed writer are removed here.
6. Verify (below), then SeaweedFS (below), then restart and **re-sweep**.
## Why bronze and quarantine are CoW, silver MoR
Bronze and `quarantine_*` use Iceberg's default copy-on-write: `DELETE` rewrites the affected files immediately and leaves no delete files. Silver is merge-on-read (ADR-0003), so its MERGEs leave position-delete files and the original data file stays referenced; only the rewrite with threshold 1 removes the old bytes. The manifest and expire steps are needed in both.
## Reintroduction window and re-sweep
Bronze is append-only and has no replay guard (F1 duplicates bronze rows by design). While the subject's records are still in Redpanda, a Spark restart or replay can append them again. After the broker is verified clean, the workflow repeats the bronze/quarantine `DELETE` and steps 1-5. Silver is protected by its tombstone (ADR-0013/0017).
## Verification
List the whole `s3://lake/` bucket (not only table paths), decode every Parquet file and search all string and binary columns (including `value_bytes`) plus footer min/max statistics, decode every Avro manifest and manifest list (bounds included), gunzip and text-search every `*.gz.metadata.json`. Raw `grep` of Parquet worked in the spike, but Avro manifests and `*.gz.metadata.json` are compressed, so grep alone is blind there and is never the evidence. Old `*.metadata.json` versions are kept and held no canary in the spike.
## SeaweedFS
Deleting an object marks the needle deleted; the bytes stay in `/data/<bucket>_<vol>.dat` until `volume.vacuum` (which needs `lock` in `weed shell`; `-collection lake` limits it to the Iceberg bucket). Garbage is read from `volume.list` (`DeletedByteCount / Size`, a few seconds behind). Compressible objects are stored gzip'd, so a grep of `.dat` can miss present data; the evidence is the garbage ratio before and after vacuum, not a grep. Whether vacuum of the live `lake` collection is clean was not spiked and is to be measured in g8-check.
## Limits
- Every number here is for one machine and one run shape; the window's wall time is to be measured in g8-check.
- Concurrent writers during a window are not supported; that is why live mode is deferred.
