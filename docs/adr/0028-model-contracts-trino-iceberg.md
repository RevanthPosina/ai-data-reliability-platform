# ADR-0028: Model contracts on Trino and Iceberg
- Status: accepted (G4, 2026-11-10); written before any G4 run, so nothing here is a result. Items marked **unverified** are not yet observed. The Measured section is added after the run of record.
## Decision
Every mart sets `contract: {enforced: true}`, and every column declares a `data_type` (Trino types: `bigint`, `varchar`, `decimal(14,2)`, `date`, `integer`, `boolean`, `timestamp(6) with time zone`). dbt compares the declared columns and types with the model's query and fails the build on a mismatch.
**What is enforced by the engine.** Keys and amounts carry `constraints: [{type: not_null}]`. `not_null` is the **only** constraint that Trino and Iceberg enforce. `primary_key` and `unique` are declared as metadata only (documentation for readers and tools), and are backed by tests: `unique`, `not_null` and `relationships` in `schema.yml`, plus singular tests in `dbt_gold/tests/`. `accepted_values` covers `journal_type` and `txn_type`.
**Negative test (fixture only).** `--vars '{contract_break_test: true}'` makes `dim_date` cast `date_key` to `varchar`. The fixture asserts that the build fails with a contract error (not a generic failure), so that a contract that does nothing would be seen.
**Static check without Docker.** `tests/test_dbt_gold_static.py` reads the YAML and asserts: contracts enforced on every mart, a `data_type` on every column, `not_null` on keys, no `store_failures`, no `materialized: view`, `full_refresh: false` on the ledger, and ephemeral staging. `make dbt-parse` runs `dbt parse` without a connection as part of `lint`.
**Tests never set `store_failures`.** It would copy rows (possibly PII) into new tables outside the inventory (ADR-0029).
**Unit tests** (`unit_tests:`) run in the fixture target only, for `dim_customer` full and incremental builds (`is_incremental` override plus a `this` input) and for the ledger legs. Live builds use `--exclude "test_type:unit"`.
**Amendment (G4 fixture, 2026-11-10): no contract on the snapshot.** With `contract: {enforced: true}` on `snap_customer_attrs`, the first snapshot run passed but the second failed in dbt-trino 1.10.6, because the snapshot staging table gets `dbt_change_type` and `dbt_unique_key` columns that the contract rejects (`missing in contract`). The snapshot is only the comparison with SCD2, so its contract was removed; contracts stay enforced on every mart (FX7 still proves a break fails the build).
## Limits
- "Contracts enforce only `not_null`" is the wording wherever contracts are mentioned. A contract does not make a primary key unique or a foreign key valid; the tests do that for the data present at build time.
- A passing test shows the property for the rows at that run. It is not a guard against later writes.
- Whether dbt-trino 1.10.6 supports contracts on incremental models on Iceberg as designed is **unverified** until the fixture runs (ADR-0030).
